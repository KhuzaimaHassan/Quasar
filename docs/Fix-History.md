## CHAT-001 — incomplete replies and current-model support

**Release record:** [PR #129](https://github.com/KhuzaimaHassan/Quasar/pull/129) records the merge commit, final checks/deployment and post-release production verification. Authenticated preview checks passed on functional commit `52f4137`; the owner approved merging on 2026-11-17. Consult the PR release record for the subsequent production outcome.

**Trigger:** An answer to “What are the latest updates in AI field?” persisted an unfinished fifth heading. Reload confirmed saved text, not viewport clipping. Historical metadata did not record finish reason, so the exact original cutoff cause remains unknown.

**Repair:** Record completion categories and safe notices, preserve partial text on errors/stops/timeouts, and flag unavailable token usage. Continue creates an explicit new turn from freshly fetched saved history, with a click lock and post-request reconciliation. Historical completion remains unknown. Hydrogen is the new-chat default; existing choices, legacy Flash-Lite aliases and lighter background calls remain supported. UTC date and no-live-search instructions prevent presenting recalled facts as verified latest news. No migration or paid grounding is introduced.

**Live-discovered stop defect:** Initial SDK/fixture checks passed, but real serverless testing showed browser abort alone could lose received text on refresh. The completed repair saves visible text through an authenticated Stop endpoint before closing the local stream. Stop and model callbacks share an owned-row database lock and server-generated generation identity in existing message JSON, so only one answer/token increment can be committed. Late callbacks cannot overwrite stopped text. Empty stops remain retryable; active turns remain stoppable after reload. Immediate cancellation of remote provider computation is not guaranteed; its generation deadline remains bounded.

**Relevant files:** [AI pipeline](AI-Pipeline.md), [API](API.md#post-apiconversationsidstop), [message metadata](Database.md#messages), [ADR-025](Decisions.md#adr-025-preserve-incomplete-chat-replies-and-separate-chatbackground-defaults), `src/lib/chat-completion.ts`, `chat-generation-store.ts`, `chat-transport.ts`, chat API/page, Stop endpoint and corresponding regression tests.

**Automated verification:** Local suite: 48 passed, three DB-only skips; the existing ingestion HTTP test needs loopback access. TypeScript, ESLint, secret scan, documentation links and whitespace passed. [CI 43909049311](https://github.com/KhuzaimaHassan/Quasar/actions/runs/43909049311) passed all three jobs and the production build on `52f4137`: PostgreSQL-enabled suite 62 passed, zero failed/skipped. Tests cover actual SDK/transport callbacks, strict Stop input, ownership, repeated stops, Stop/completion races, citations, empty-stop retry, stale generations and transaction rollback. Check latest PR-head CI before release too.

**Browser verification, 2026-11-16:** The initial actual-page synthetic loopback fixture passed notices, historical unknown status, safety-filter policy, double-click single request, reload, failed refresh and quota recovery. These fixture checks are distinct from live evidence. In the authenticated cloud preview, Hydrogen returned three complete current-events limitation bullets with the correct date; a full 80-step answer survived reload. ## MEM-001 — preserve manual memory corrections

**Release record:** [PR #128](https://github.com/KhuzaimaHassan/Quasar/pull/128) records the current merge commit, checks and deployment outcome. The reviewed additive migration was applied to the intended shared database on 2026-11-16, and authenticated preview feature verification passed before merge. Consult the PR's release verification for the subsequent production result.

**Trigger and defect:** A user adds or corrects a long-term memory. Later background extraction finds the same `(userId, scope, key)` in chat history and used to overwrite the saved value and confidence unconditionally.

**Repair:** Manual adds/edits set `isUserManaged=true` and confidence 1. Automatic inserts set false; their atomic PostgreSQL upsert updates only false rows. Protected rows keep their values, confidence and timestamp even if extraction races a manual edit. The UI identifies protected rows. A new additive migration protects every historical row because old provenance is unknown, preserving all values/confidence.

**Relevant files:** [Memory behavior](Memory.md), [API](API.md#memory), [database](Database.md#memory), [ADR-024](Decisions.md#adr-024-user-managed-memories-take-precedence-over-extraction), [release ordering](Deployment.md#memory-protection-release), `src/lib/memory-store.ts`, `tests/memory-protection.test.ts`.

**Verification:** Local `npm test`: 37 passed, two isolated-database cases explicitly skipped. TypeScript, ESLint, whitespace, secret scan and relative documentation-link checks passed. The actual Memory page/query hooks were exercised in fresh Chrome against a synthetic loopback API: manual add, edit-to-protected, cancel, reload and five widths 320–1440px passed. This is UI evidence, not a live account test. [CI run 43837192996](https://github.com/KhuzaimaHassan/Quasar/actions/runs/43837192996) passed all three jobs for the implementation commit: the isolated PostgreSQL job passed 44 tests with zero skips, including backfill, concurrent first writes/edits and ownership; the frontend job passed 37 with its two DB-only skips and passed the production build. Check the latest PR head's checks as well before release. No real user memories were changed.

**Authenticated preview, 2026-11-16:** Real chat/model extraction created a synthetic automatic project memory without protection. Editing it from `cobalt` to `amber` made it Protected; a separate manual entry was protected on creation. Both survived reload, and cancelling an edit discarded the draft. A later three-turn chat repeated the old `cobalt` value alongside a new probe. The probe appeared automatically while the corrected value remained `amber` and Protected, demonstrating that extraction ran without overwriting it. Each reply's persisted history was confirmed before the next turn. Memory layouts were visually checked at 390×844, 768×1024 and 1440×1000 with no horizontal page overflow. Only clearly labeled synthetic QA data was added/edited; it was retained for review.

**Rollout:** The owner-approved `20261116090000_protect_user_managed_memories` migration ran in preview build commit `b68e0cc`, before new code used the database. Its guarded step verified the reviewed SQL checksum, only that pending migration, recorded history, protected legacy rows and unchanged values/confidence. Vercel's existing write-only connection settings stayed inside its build environment. The temporary deployment exclusion and migration build hook were removed afterward; normal builds do not automatically migrate. CI's database remains isolated from the account database. Merge is conditional on the authenticated preview check and green final-head CI; the PR release record tracks the production deployment and post-merge smoke check.

**Limits:** Memories remain user-wide. Deleting a fact does not erase its source chat or prevent later re-extraction. No permanent-forgetting or unprotect control is introduced.

## Continuing a fix

1. Read the matching feature guide and linked PR before changing behavior. Check current main and any open PRs so a merged repair is not repeated.
2. Reproduce with synthetic data. Record the trigger, expected result and actual result. Keep production account data, signed URLs, credentials and private conversation IDs out of public notes.
3. Update this file and the relevant guide in the same PR. Add focused regressions for data/authorization/concurrency changes and browser evidence for UI changes.
4. Record local, fixture, CI, preview and production results separately, including skipped checks and known limits. A successful build is not a live functionality test.
5. After approval and merge, record the PR, merge commit, migration ordering, deployment state and production smoke result. Keep unresolved items explicitly in review rather than marking them fixed in production.

## Known boundaries

Free-tier services can sleep and provider models/quotas can change. Agent generation retries do not create a durable worker or cancel an already running backend task. Document retries do not provide OCR. Memory remains user-wide; permanent forgetting is not implemented. These are separate capabilities, not regressions silently claimed as solved by the repairs above.
